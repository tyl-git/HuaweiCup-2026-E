# Q1 视频复核版本说明

## 为什么需要标准化

部分暂存 MP4 的容器元数据声明帧数大于实际可解码帧数。播放器可能按错误的声明帧数显示时长，导致画面时间轴看起来比真实内容更长。这个问题属于视频容器/时间戳问题，不是音频、转写或模型特征的问题。

## 处理方法

原始视频未修改。对 100 个复核视频逐个执行以下流程：

1. 使用 OpenCV 顺序解码，统计实际可读取的视频帧数。
2. 使用原始帧率计算实际视频时长。
3. 使用 FFmpeg 重新编码为连续时间戳的 H.264/AAC MP4，重置视频和音频 PTS，并写入 faststart 元数据。
4. 使用 FFprobe 统计输出的声明帧数、实际读取帧数和时长。

## 验证结果

- 标准化输出：100/100
- 输出视频均可读取
- FFprobe 检查中，输出视频的 `nb_frames` 与 `nb_read_frames` 一致
- `sample_0001`：输出为 165/165 帧，30 FPS，5.500 秒；源文件曾声明 261 帧但实际只有 163 帧
- 少数 29.97 FPS 视频在 OpenCV 的浮点取整下可能出现约 2 帧的读取计数差异；以 FFprobe 的完整解码计数和播放器连续时间轴为准，不影响复核

## 对特征和训练的影响

本处理只用于人工播放和时间显示校验，不替换原始数据，不重跑 OpenFace、音频特征、BERT 或问题二训练结果。若人工复核发现转写或词级时间边界错误，应在复核日志中记录，再单独决定是否修订对齐数据。
