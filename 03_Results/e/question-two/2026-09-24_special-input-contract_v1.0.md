# 附件三与附件四对齐版输入结构核查

核查范围仅限附件三 30 个和附件四 20 个对齐版 `.pkl` 的字段、形状、类型、有限值及序列掩码。原始文件只读；未查看视频、标签或预测结果，未用专项集训练、选模型、选阈值或估计性能。逐文件字段、零值区间和 SHA-256 见 [同名 JSON](2026-09-24_special-input-contract_v1.0.json)。下文索引从 0 开始，区间采用左闭右开 `[start,end)`。

| 专项集 | 文件数 | 文件结构 | 文本 | 音频 | 视觉 | BERT 输入 |
| --- | ---: | --- | --- | --- | --- | --- |
| 附件三 | 30 | `{'test': {'text_bert', 'audio', 'vision'}}`，每文件 1 个样本 | 无预计算 `text` | `(1,50,74)` `float32` | `(1,50,35)` `float32` | `(1,3,50)` `float32`，数值均为有限整数 |
| 附件四 | 20 | 单样本字典，另有 `id`、`raw_text` | `(50,768)` `float32` | `(50,74)` `float64` | `(50,35)` `float64` | `(3,50)` `int64` |

50 个文件均无显式 `length` 字段。`text_bert` 的第 2 路 attention mask 在所有文件中为连续有效前缀：附件三长度 8 到 50，附件四长度 13 到 50；第 0 位为 `[CLS]`，最后有效位为 `[SEP]`，其余 token ID 在 attention 为 0 时为 0。两组均无 attention 内部空洞，也无 attention 为 1 而 token ID 为 0 的位置。可用 attention 定义**序列范围**，再排除首尾特殊 token 得到内容范围。不能用文本嵌入是否全零推断 padding：附件四 768 维 `text` 在 attention 为 0 的位置仍有 396 个非零向量。

附件三内容位置有 131 个全零音频向量、135 个全零视觉向量，分别涉及 27 个文件；这些位置必须保留原有索引和输入长度，单独记录模态可用性，不能删除或向前压缩。附件四音频没有全零内容位置；视觉在 `13.pkl` 的 50 个位置**全部为零**，其中 30 个是内容位置 `[1,31)`。此例不能作为正常视觉观测输入解释，应保留样本并标记视觉不可用。两组的音频和视觉在 `[CLS]`、`[SEP]` 对应位置均为全零；这两个位置不属于内容缺失统计。全零是可观察的数值现象，文件中没有额外的缺失来源标签，不能据此断言每个零都是人工施加的缺失。

训练与专项推理需要统一输入接口。建议读入时将附件三 batch 维和附件四无 batch 维规范成 `[B,50,*]`，核验附件三 `text_bert` 的 float32 值确为整数后转换为整数 token 输入，音频、视觉转换为统一浮点类型，同时保留 `sequence_mask` 和独立的模态有效掩码。**关键不兼容点：附件三没有预计算的 768 维 `text`。** 如果模型在附件二训练时只读取 `text`，它不能直接推理附件三；应在附件二训练/验证和专项推理统一使用 `text_bert` 编码路线，或先独立证明生成的 768 维表示与训练用 `text` 相容。不可仅在附件三临时换一个文本编码器。

附件三的 `text_bert` 未呈现内容位置的 token ID/attention 归零后又出现有效 token 的情形，因此当前文件**不能证明文本局部缺失的编码语义**。模拟文本缺失时应保留缺失前的序列范围，并使用独立缺失掩码；不能把局部 token 归零造成的 attention 改变误认为句尾 padding。附件四的共同 `50` 序列位置也不是秒级时间戳，关键证据回到原视频时必须另行验证位置到原片段的映射。
